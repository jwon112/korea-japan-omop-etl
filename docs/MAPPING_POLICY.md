# Mapping Policy

## Shared Rules

1. Load and validate a complete Athena vocabulary before clinical ETL.
2. Use only active standard concepts in the expected OMOP domain.
3. Preserve a valid source event when no defensible mapping exists and set its
   standard concept ID to `0`.
4. Do not improve an apparent mapping rate by assigning a standard concept
   from the wrong domain.
5. Keep source values in the corresponding `*_source_value` columns for audit.
6. Mapping expansion is frozen during closeout. Fix incorrect mappings, but do
   not add speculative mappings solely to raise coverage.

## Korea NHIS-NSC

- The target CDM also serves as the default mapping database.
- `source_to_concept_map` is generated from active Athena `Maps to`
  relationships whose targets are active standard concepts.
- KCD diagnosis, EDI drug/procedure/device, LOINC measurement, and UCUM unit
  mappings are resolved through the loaded vocabulary and SQL rules.
- Conditions with no valid Condition target remain with concept ID `0`; they
  are not dropped because another-domain mapping happened to exist.
- Korea conditions are loaded only through an accepted visit. One source
  diagnosis may expand to multiple active standard Condition targets; an
  unmapped source diagnosis is retained once with concept ID `0`.
- Korea 30T/60T drug candidates are each scanned once and must attach to an
  accepted claim visit. Active standard Drug targets are retained; unmapped
  drug candidates remain once with concept ID `0`. Drug starts outside their
  visit are rejected, starts after death are rejected, and exposure ends are
  capped at death.
- Event IDs are deterministic and allocate room for source codes that map to
  more than one standard target. The ETL fails if a code exceeds the 99-target
  allocation.
- Detail source `AMT` is captured in `SEQ_MASTER` and reused for Drug,
  Procedure, and Device cost rows. Cost-source recovery does not depend on
  clinical type concepts.
- Annual eligibility rows define contiguous observation periods, bounded by
  estimated birth year and recorded death month.
- Claim and health-check visits are loaded only when their complete start/end
  span is contained in one observation period. This excludes impossible
  post-death claims and avoids extending enrollment or death boundaries from
  contradictory event rows.
- The obsolete destructive data-cleansing phase is not packaged. Reviewed
  temporal and relational boundaries are enforced during insertion and QA.

## Japan JMDC

- The relational JMDC pipeline uses `JP_CLAIMS` as the authoritative cohort
  and visit spine. Only members represented by a claim are loaded to
  `person`, and each valid claim becomes one `visit_occurrence`.
- For those claim-backed persons, valid `JP_PATIENT` observation start/end
  values define the enrollment observation span. Claims months are only a
  fallback when the patient span is unavailable.
- Diagnosis, drug, and procedure rows must attach through their
  `(member_id, claim_id)` to a claim-backed visit. Detail tables are not used
  to invent visits.
- Claim admission/discharge dates are preferred; the claim month is the final
  non-synthetic visit-date fallback.
- Condition codes use normalized ICD-10 source values and active standard
  Condition `Maps to` relationships.
- Drug codes require an active standard Drug target. ATC classification
  concepts are not stored as `drug_concept_id`.
- Procedure mappings use the reviewed JMDC crosswalk embedded in
  `110.Procedure_occurrence_japan.sql`.
- `procedure_concept_id` accepts only active standard Procedure concepts.
  LOINC Measurement concepts may document test meaning but are not written
  into the Procedure domain.
- Consultation, interpretation, prescription, dispensing, management, and
  other administrative fee rows remain source events with concept ID `0`.
- Cost is payer-point based and minimal: unavailable currency and paid-by
  components remain null.
- Events with no defensible source or claim date are not assigned a synthetic
  `1900-01-01` date.
- `location` and `observation` are intentional no-op transformations for the
  current source model.
- `device_exposure` is deferred until a reviewed JMDC material-to-Device
  mapping exists.
- `care_site` requires `JP_MEDICAL_FACILITY`.
- `measurement` requires `JP_ANNUAL_HEALTH_CHECKUP` and maps supported fields
  to LOINC and UCUM.
- `drug_era`, `dose_era`, and `condition_era` are optional derived tables and
  are not generated by the Japan closeout pipeline.

### Korea derived eras

- `drug_era` and `condition_era` are optional derived outputs. When selected,
  mapped standard concepts are merged with a 30-day persistence window using
  interval running maxima.
- `dose_era` is intentionally not transformed. NHIS claim quantity is not a
  normalized dose, and the current ETL has no standard dose unit concept.
  Grouping package quantities across drugs with a NULL unit would create a
  misleading clinical artifact, so no executable step is packaged.
- Era generation, indexing, and foreign-key creation require explicit
  `--only` selection. They are not part of the default post closeout command.

## Coverage Reporting

Report both source-row retention and standard-concept coverage. A low mapping
rate is not automatically a defect when the source has no standard bridge or
the row represents an administrative fee. Report invalid-domain assignments
as errors, not as mapped rows.
